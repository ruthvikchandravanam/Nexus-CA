# ADR-0010: Software-encrypted private keys (no HSM) in v1.0

- **Status:** Accepted
- **Date:** 2026-05-13

## Context

The most security-sensitive choice in a CA is where CA private keys live. The two options at this scale are:

1. **Software** — generate, store, and use keys inside a server process; protect at rest with an encryption key (KEK).
2. **Hardware Security Module (HSM)** — keys live inside a tamper-resistant device; signing happens on the HSM; the private key bytes never leave.

The BRD lists HSM integration as **Out of Scope** for v1.0.

## Decision

Use software-encrypted private keys in v1.0:

- CA private keys are generated by BouncyCastle inside the Crypto API process in VLAN 4.
- At rest, each private key is AES-256-GCM-encrypted with a `CRYPTO_KEK` injected via environment variable.
- The Crypto API exposes only operations that take inputs and return public material — private keys never leave VLAN 4 and are never returned from any endpoint.

## Consequences

Pros:

- Significantly faster delivery: no HSM procurement, no HSM operational learning curve, no vendor-specific JCA provider.
- Lower cost.
- The architectural seam (Crypto API) is HSM-ready: swapping the BouncyCastle-backed signer for a PKCS#11-backed signer in v2 is a localized change.

Cons / costs:

- KEK compromise is now a single security boundary breach (see [threat-model.md — residual risks](../security/threat-model.md#6-residual-risks)).
- Loss of the KEK renders restored backups unusable (acknowledged in [tools.md note](../../3-Implementation/tools.md#crypto-db) and [backup-restore-runbook.md §4.3](../../3-Implementation/backup-restore-runbook.md)).
- For very-high-value Root CAs (e.g., the company's master signing identity), software-only storage may not meet some compliance regimes.

## Future direction

HSM integration is a candidate for v2 limited to Root CAs (highest value) while leaving Intermediate CAs in software for operational ergonomics. PKCS#11 is the universal HSM interface; BouncyCastle has a PKCS#11 JCA provider.
